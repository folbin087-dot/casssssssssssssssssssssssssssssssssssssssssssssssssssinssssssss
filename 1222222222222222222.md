

## 1) Где взять API-ключ

API-ключ привязан к **магазину** (`shop`).

- В кабинете мерчанта:
  - открыть раздел `Магазины`
  - создать магазин (или открыть существующий)
  - взять поле `api_key`
- Через API кабинета мерчанта:
  - `GET /api/merchant/shops` (Bearer JWT)
  - в ответе у каждого магазина есть `api_key`

Каждый запрос публичного API должен содержать заголовок:

`X-API-Key: <ваш api_key>`

---

## 2) Базовые публичные endpoints

Все вызовы ниже: `/api/public/*` + `X-API-Key`.

- `POST /api/public/payment` — создать заявку
- `GET /api/public/payment/:guid` — получить статус заявки
- `POST /api/public/payment/:guid/dispute` — открыть спор

---

## 3) Создание заявки

## Request

`POST /api/public/payment`

```json
{
  "amount": 1500,
  "currency": "RUB",
  "payment_way": "CARD",
  "payment_type_id": null,
  "external_id": "order_10001",
  "traffic_group_id": 4,
  "customer_data": {
    "email": "buyer@example.com"
  }
}
```

Ключевые поля:

- `amount` — обязательное, > 0
- `currency` — обычно `RUB`
- `payment_way` — код или алиас (см. раздел ниже)
- `external_id` — ваш ID заказа
- `traffic_group_id` — опционально, если хотите конкретную группу

## Response (успех создания)

Обычно `201` и структура pending/invoice с `payment_id`, `status`, реквизитом (если уже выдан) и мета-полями.

---

## 4) Статусы сделки

В системе используются (минимум для интеграции):

- `invoice` — заявка создана, ждёт назначения/принятия
- `pending` — реквизит выдан, ждёт оплату
- `success` — успешно подтверждена
- `cancelled` — отменена
- `expired` — истекла
- `dispute` — спор

Проверка статуса:

`GET /api/public/payment/:guid`

---

## 5) Webhook/callback события

Система отправляет POST на URL магазина:

- `callback_url` — основные события
- `success_url` — дубликат **только** для `payment.success` (если заполнен)

Заголовки:

- `X-Webhook-Event: payment.<event>`
- `X-Webhook-Signature: <hmac_sha256>` — если у магазина заполнен `webhook_secret`

Основные события:

- `payment.pending`
- `payment.success`
- `payment.cancelled`
- `payment.expired`
- `payment.dispute` (обычно при ручном resend/споре)

Тело webhook включает как минимум:

- `payment_id`, `shop_id`, `amount`, `currency`, `status`, `external_id`
- `requisite` (если есть): `bank`, `card`, `owner`, `payment_way`, `payment_way_en`, `qr_url` (для QR)
- `created_at`, `paid_at`, `expired_at`

Retry-логика webhook:

- до 3 попыток
- задержки: ~1 мин, ~5 мин, ~15 мин

## 6) Способы оплаты (канон + API код)

Текущий канонический набор:

- `Перевод на карту` → `CARD`
- `СБП` → `SBP`
- `СБП QR` → `QRSBP`
- `НСКП` → `NSPK`
- `Пополнение моб` → `Mobtras`
- `Alifa - Alifa` → `AlifaTrasc`
- `PSB - PSB` → `PSBTRAS`
- `SBEP - SBEP` → `SBEPTRAS`
- `Click UZ QR` → `UZQR`
- `Перевод по номеру счета` → `Trashernumvmer`

Проверить актуальный список можно через:

`GET /api/payment-methods/ways`

---

## 7) Алиасы (тоже принимаются)

Для совместимости принимаются и нормализуются:

- `Card`, `card`, `card_transfer`, `Карта` → `Перевод на карту`
- `mobile_topup`, `transfer_by_phone`, `Пополнение моб. телефона`, `Перевод по номеру телефона` → `Пополнение моб`
- `Alfa-Alfa` → `Alifa - Alifa`
- `gaz-gaz` → `PSB - PSB`
- `Sber-sber` → `SBEP - SBEP`

## 8) Минимальный пример интеграции (curl)

Создать заявку:

```bash
curl -X POST "https://plaidprocessing.com/api/public/payment" \
  -H "Content-Type: application/json" \
  -H "X-API-Key: <YOUR_API_KEY>" \
  -d '{
    "amount": 1500,
    "currency": "RUB",
    "payment_way": "CARD",
    "external_id": "order_10001"
  }'
```

Проверить статус:

```bash
curl "https://plaidprocessing.com/api/public/payment/<GUID>" \
  -H "X-API-Key: <YOUR_API_KEY>"
```

## 9) Частые ошибки

- `401 API ключ не предоставлен / Неверный API ключ`
  - проверьте `X-API-Key`
- `400 TRAFFIC_GROUP_NOT_ALLOWED`
  - указанная `traffic_group_id` не подключена к вашему аккаунту
- `503 NO_REQUISITE`
  - сейчас нет подходящего реквизита
- `400 DUPLICATE_ACTIVE_SUM*`
  - уже есть активная заявка на такую сумму
